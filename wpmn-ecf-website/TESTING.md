# Feature testing requirements

Every feature change must include behavior tests in the same pull request. Cover successful use, invalid input, denied access and relevant failure/retry behavior. Describe the observed behavior in the PR, not just the number of tests. A refactor must preserve existing behavior tests. A documentation-only change can state that no executable behavior changed.

Run `npm run test:unit` for fast function tests, architecture checks and the synthetic-data sanitizer. This runs on every push and PR. Run `npm run test:integration` for API journeys through a synthetic SQLite database, transaction conflicts, private/public data separation, local D1 and migration behavior. Integration checks also run on PR candidates and merge-queue candidates before merging, then on pushes to main and sites-wpmn-ecf. Requiring only post-merge tests would leave the target branch unprotected. Type checking and the production build remain in the integration job.

Both commands enforce at least 60 percent line, branch and function coverage. The unit denominator covers every shared library under lib plus app/chatgpt-auth.ts. The integration denominator also covers every API route and the migration/sanitizer libraries. Tests explicitly load all shared libraries so an untested new library cannot quietly disappear from the denominator. New API routes must be classified by the existing route inventory test and imported/exercised in integration tests. The low-coverage fixture verifies that a green assertion suite still fails below the floor. The test loader strips TypeScript types while retaining source positions for coverage.

Coverage excludes lib/defaults.ts (approved static ministry text) and lib/write-sql.ts (SQL string constants). SQL behavior remains checked against SQLite and local D1. Tests, dependencies and framework scaffolding are excluded. These are business-logic coverage gates, not a claim of 60 percent coverage of the whole visual website. React page/component line coverage is not measured here. API journey tests are not browser end-to-end tests. Existing main-branch standalone app coverage is also outside these website gates.

The website delegates sign-in and sign-out to Sites. Tests verify missing identity, safe redirects, recognized editor roles and denied permissions. They do not verify the provider's password, account lockout, cookie revocation or resistance to forged headers on a different hosting platform. A future local password feature must add login, logout, incorrect-password, throttling and lockout tests in its own PR.

Use only synthetic records and local database/storage doubles. No production pastoral records, real payments or outbound notifications are required for these tests. Never lower the floor, remove covered paths or replace behavior assertions with source-text checks to make a feature pass.

Repository administration must require `Website unit tests and coverage`, `Website security tests`, `Secret scanning` and `AI production review` on both target branches. Workflow failure alone does not prevent an administrator from merging unless branch/ruleset settings enforce it. That configuration remains separate from this code change.

Run `npm run build`, `pnpm exec playwright install chromium --with-deps --only-shell`, then `npm run test:browser` for production-build browser journeys. The suite runs Chromium in Indian desktop and Ghanaian mobile locale/time-zone contexts, covering public content/assets, form consent, locale preferences, real local contact submissions, anonymous prayer, denied editor API access and the sitemap. It creates a fresh synthetic local D1 database and local R2 state, never production data. GitHub runs these journeys in the required integration job before merge. Sites identity-provider login remains a provider boundary.

Calendar dates are stored as YYYY-MM-DD without a time-zone conversion. Timestamp displays use the viewer's language and time zone. Visitors can correct language and time-zone preferences for human follow-up. Event times retain the editor-selected IANA zone, defaulting to Asia/Manila for existing Philippine gatherings. This website does not offer local customer accounts, automated email scheduling or integrated payment checkout; payment acceptance and currencies require the external payment-provider account.
